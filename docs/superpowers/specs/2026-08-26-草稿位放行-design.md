# 2026-08-26　草稿位放行（`draft: true`）设计

## 要解决什么

放行一篇校验未通过的文章，人工要做五件机械事：改内容、删文件开头的
HTML 注释、去掉文件名的 `seed-` 前缀、把文件从 `_review/` 移到
`src/content/posts/`、往 `published.json` 补一条记账。

在 GitHub 网页和手机上，后四件基本做不动 —— 网页版没有「移动文件」，
改名要在路径输入框里手打，`published.json` 要手写一段 JSON。

**根因不是步骤多，是同一个状态存在三个地方：**

| 状态载体 | 说明 |
|---|---|
| 文件在哪个目录 | `_review/` = 待放行，`src/content/posts/` = 已发布 |
| 文件开头的 HTML 注释 | 记着没过哪些检查 |
| `published.json` | 选材去重的账本 |

三份状态要人工手动对齐，漏一份就出事。实测已经出过两次：

1. **HTML 注释在 GitHub 预览里整段不显示**（Markdown 渲染器吃掉
   `<!-- -->`），人打开文件根本看不到问题清单，得点 Code 或 Raw 才看得见
2. **master 上真实发生过一次漏记账**：`HCP鉴定与定量` 已经手工搬进
   `posts/` 并上线，`published.json` 里没有对应记录 —— 引子通道按
   `published.json` 的 `seed` 字段去重，那篇笔记因此仍算「没用过」，
   下一次定时任务会重新挑中它、再烧一次 DeepSeek、覆盖已发布的文章

## 设计

**状态收敛成一处：文章 frontmatter 里的一行。**

```
流水线永远写 src/content/posts/<slug>.md
├─ 校验全过 → 普通文章，直接上线
└─ 校验没过 → 同一个文件，frontmatter 多两项：
     draft: true
     reviewNotes:
       - "出现源文没有的数据: ['1.8', '12kda']"
```

| 动作 | 怎么做 |
|---|---|
| 放行 | 删掉 `draft: true` 那一行 |
| 退稿 | 删掉整个文件 |
| 记账 | 不用管，流水线每次运行自动对账 |

`_review/` 目录取消。

### 为什么是 frontmatter 而不是别的载体

评估过三个，取第一个：

| 方案 | 放行动作 | 否掉的原因 |
|---|---|---|
| **frontmatter `draft: true`**（采纳） | 删一行 | — |
| 文件名 `<slug>.draft.md` + glob 负向匹配 | 改文件名 | 站点侧零改动、泄漏不可能，但改名正好卡在手机上最难做的那一步 |
| 保留 `_review/` + `--approve` 命令或 Actions 按钮 | 跑一次 CI | 还是得开终端或等 CI；且是造个机器人去干 `git mv` 的活，多一层机器多一层出错 |

`reviewNotes` 用 YAML 列表而不是 HTML 注释，就是为了让 GitHub 预览
显示得出来 —— 上面那条实测踩坑直接决定了这个选择。

### `published.json`：改 key + 自愈

**改 key。** 现在用 `primaryTag` 当 key，而同一个三级标签下会有多篇文章
（`_review/` 里 ELISA 和 HCP鉴定与定量 的 `primaryTag` 完全相同）。
两篇都记账时后写的静默覆盖先写的，被覆盖那篇于是变回「没发过」，
会被重新生成。改用 **slug** 做 key —— slug 就是文件名，天然唯一。
记录里补一个 `tag` 字段，供「相关阅读」按标签前缀检索。

**自愈。** 每次运行开头扫一遍 `src/content/posts/`：

- 有文件、没记录 → 按 frontmatter 回填（tag / slug / title / seed / draft）
- 有记录、没文件 → 删掉记录（人删文件 = 退稿，那篇笔记重新入列）

于是人工永远不需要碰这个文件，手工搬过去的文章也会被自动收编。

**回填记录不带 `source_hash`。** `pick_next` 原本靠 `source_hash` 变化
判断「源笔记改了，该重发」。回填时拿不到 vault 算不出哈希，留空即可，
并把 `pick_next` 改成「没有 `source_hash` 就当作已发布，不重发」——
人工放行过的文章不该因为源笔记改了个错别字就被悄悄重写一遍。

### 草稿怎么保证不上线

`draft: true` 的文章在 `src/content/posts/` 里，和正式文章同一个目录，
Astro 默认会把它们一起构建出来。全站有 9 处 `getCollection('posts')`，
逐处加过滤迟早漏。

收敛成一个 `src/lib/posts.ts` 的 `listPosts()`，内部一次过滤；再加一条
自检：grep 全仓库，包装器之外出现裸 `getCollection('posts')` 就让自检
失败。这条是按本仓库「校验器是安全阀」的规矩加的 —— 不加的话，以后新增
一个页面忘了过滤就把未审文章放出去了。

`getEntry` / `getCollection('series')` 不在拦截范围内：系列是显式点名
某篇文章，指到草稿属于写 `series.json` 的人自己的错，构建期本来就会因
「引用了不存在的文章 id」而失败。

## 动了哪些文件

| 文件 | 动作 |
|---|---|
| `pipeline/main.py` | published.json 改 slug 做 key、新增 `reconcile()`、`pick_next` 忽略无哈希记录 |
| `pipeline/seed.py` | 统一写 posts/、未过校验加 draft 标、删 `pending_review()` |
| `pipeline/verify.py` | 无改动（校验规则一条都不放宽） |
| `pipeline/notify.py` | 提示语改成新动作 |
| `src/content.config.ts` | schema 加 `draft` / `reviewNotes` |
| `src/lib/posts.ts` | 新增，`listPosts()` |
| `src/pages/*.astro`、`src/lib/series.ts` | 9 处调用点换成 `listPosts()` |
| `pipeline/test_pipeline.py` | 补自检 |
| `.github/workflows/publish.yml`、`sample.yml` | 提交清单去掉 `_review` |
| `_review/` | 存量 9 篇转成 draft 迁进 posts/，目录删除 |

## 验证

- `python pipeline/test_pipeline.py` 全绿，新增自检覆盖：draft 落盘、
  自愈回填与销账、slug 做 key 不再互相覆盖、相关阅读跳过草稿、
  裸 `getCollection` 泄漏
- `npm run build` 通过，且构建产物里**不含**任何 draft 文章的页面
