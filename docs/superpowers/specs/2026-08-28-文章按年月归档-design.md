# 文章目录按年月归档 — 设计文档

日期：2026-08-28
状态：已评审（用户在对话中确认三项落地方式：`YYYY-MM` 命名、文件名不变、
不额外建索引；并纠正了月份取值规则——见决策记录最后一行）
分支：`claude/organize-posts-by-year-month-bf32eb`

## 1. 背景与目标

`src/content/posts/` 现在是平铺目录。2026-08-28 已有 17 篇文章挤在一起，
且这个数字只会随流水线持续产出而增长。校验没过的文章（`draft: true`）跟
正式文章同住一处（`src/content.config.ts` 里写明的既有设计——放行只是
删掉一行 frontmatter，不挪文件），人工想找"哪几篇还等着放行"就要翻遍全部
文章，是大海捞针。

目标：按年月（`YYYY-MM`）把文章分进子文件夹，人工翻找草稿时只用扫一个月
的量。**不改变"草稿与正式文章同住一处"这个既有设计**，只是把"一处"从
一个平铺目录变成按月分的多个子目录。

## 2. 决策记录（对话中已与用户确认）

| 决策项 | 结论 | 理由 |
|---|---|---|
| 月份文件夹命名 | `YYYY-MM`（如 `2026-08`） | 跟仓库里 `published_at` 字段、devlog 文件名（`YYYY-MM-DD-标题.md`）的日期风格一致；纯 ASCII，对 shell/glob/排序更省心 |
| 文章文件名（slug） | **保持不变**，只挪目录，不加日期前缀 | slug 同时是 URL 路径（`entry.id`）、`published.json` 账本的 key、`series.json` 里系列文章的引用——三处共享同一个字符串。改文件名等于要同步改这三处，且和 title 本身是两回事：title 是给人看的完整句子（例：`hcp定量-ibaq.md` 的 title 是"宿主细胞蛋白定量中的iBAQ无标记蛋白质组学方法：原理、性能比较与工作流程"），slug 是稳定标识符，两者本来就该脱钩，这是仓库里已有的约定，本次不变 |
| "最新在顶部" | 不额外建索引，只保证按时间正序命名 | GitHub 网页版、VS Code 侧边栏、`ls`、git 等标准工具浏览目录都是字母序（旧→新），没有命名手法能让它们"自动倒序显示"，除非另外维护一份索引文件。`docs/devlog/` 已经是这个先例：文件本身正序排列，靠 `README.md` 的"目录"小节人工维护倒排列表。本次范围里不做等价的索引，成本（流水线每次发布后要同步维护）和当前"减少翻找草稿"的诉求不成比例 |
| 月份文件夹的取值来源 | **不读 frontmatter 的 `date` 字段**，四个写入点各自用"这次运行的当天"直接算月份 | 最初设计想直接用 `date` 字段，用户指出问题：`pipeline/drafts.py`（人工投稿通道）的 `date` 允许回溯——优先取稿子里手写的旧日期，其次取 `drafts/` 里稿子首次提交的 git 日期（`_git_first_commit_date`），都可能早于稿子真正被流水线处理、落进 `posts/` 的那天。若归档月份跟着 `date` 走，"今天刚落地的稿子"可能被塞进几个月前的文件夹，找不到刚落地的东西，违背这次改动的目的。改成月份直接取"运行当天"后，`date` 字段继续只管文章自己显示的日期（站点排序、frontmatter），跟归档目录彻底脱钩。三条自动化通道（`run_auto`/`seed.process`/`routinerun.run`）不受影响：它们的 `date` 本来就是当天现算的，跟"运行当天"永远同一天 |

## 3. 受影响范围与改动内容

探索代码后确认：这些改动没有"要不要做"的选择，只有"必须同步改，否则静默出错"——不需要用户再拍板。

### 3.1 流水线依赖 `posts/` 平铺的地方（5 个模块）

`pipeline/main.py` 的 `reconcile()` 用 `posts.glob('*.md')`（不递归）把磁盘上
的文章跟 `published.json` 对账；`pipeline/seed.py` 的 `related_published()`
用 `posts_dir / f"{slug}.md"` 直接拼平铺路径找已发布文章的标题；`main.py`
的 `run_auto()`、`seed.py` 的 `process()`、`drafts.py` 的 `run_drafts()`、
`routinerun.py` 的 `run()` 四处写入点都直接 `posts_dir / f'{slug}.md'`。
分月份子目录后不改的话：

- `reconcile()` 找不到任何文件，把 `published.json` 现有 16 条记录当"文件
  没了"全部销账（下一次自动/引子通道跑起来会把已发布内容当没发布过，
  重新烧一次 DeepSeek 重发一遍——`docs/devlog` 里已经记录过一次同类事故：
  《排查"定时发布看不到新文章"》）
- 新文章继续写回平铺的 `posts/`，一次自动发布就把刚做完的分类打回原形
- "相关阅读"链接找不到已挪走文章的标题，静默退化成显示 slug

`repair.py` 的 `run()` 只按 `posts_dir.glob('*.md')` 找带图片占位的已有
文件（不涉及落点计算，只是扫描），同样需要改成递归，否则分月后直接扫不到
任何待补图的文章。

**改法**：`main.py` 新增两个共享函数（`main.py` 已经是文章生命周期的共享
枢纽——`assemble_frontmatter`/`record_published`/`load_published`/
`reconcile` 都在这，`seed.py` 已经 `import main as mn`；`main.py` 对
`drafts`/`repair`/`routinerun`/`seed`/`manual` 全部是函数体内延迟 import
避免循环引用，这是仓库里已经在用的模式，新开模块反而是引入这个仓库没有的
第二套约定）：

- `_all_posts(posts_dir)`：递归 glob（`**/*.md`）拿到 `{slug: Path}`，替掉
  `reconcile()`、`related_published()`、`repair.py` 里各自的平铺 glob
- `post_path(posts_dir, slug, month)`：`posts_dir/month/slug.md`，`month`
  由调用方传入（不在函数内部读 frontmatter），供四个写入点统一使用

`seed.py` 的 `process()` 是唯一会对已存在 slug 整篇覆盖重写的通道（人工
改完源笔记后重跑同一篇引子；`run_auto` 靠 `pick_next` 天然不会选中已发布
的，`drafts`/`routinerun` 遇到重名直接报错跳过，不覆盖）。重写时月份取
"运行当天"，如果跟旧文件所在月份不同，写入前用 `_all_posts` 查到旧路径
并删除，避免同一篇文章在两个月份文件夹里各留一份孤本。

`drafts.py`、`routinerun.py`、`repair.py` 目前不 `import main`，需要各自
加一行 `import main as mn`——`main.py` 已经用延迟 import 处理了这几个
模块，加这行不会产生循环引用。

### 3.2 Astro：`entry.id` 被用作 URL 和系列匹配

`src/pages/posts/[...slug].astro` 直接 `params: { slug: entry.id }`；
`src/lib/series.ts` 用 `entry.id` 匹配 `series.json` 里的 `post` 字段。
Astro 的 `glob()` loader（`src/content.config.ts`）默认把子目录路径编进
`id`，分文件夹后不处理的话：已发布文章的 URL 会全部改变，`series.json`
里的引用会全部对不上（这属于 `loadSeries()` 里故意设计的硬校验，会让
构建直接失败，不会静默上线，但同样要避免）。

**改法**：`glob()` loader 加 `generateId`，返回值固定为文件名（不含扩展名、
不含目录前缀），保证 `entry.id` 与现在的 slug 完全一致，路由和 `series.json`
匹配零改动。

### 3.3 现有文章迁移

17 篇现存文章的 `date` 全部落在 2026-08，`git mv` 进新建的
`src/content/posts/2026-08/`，保留 git 历史。一次性操作，不写迁移脚本、
不留在流水线代码里。

### 3.4 文档

`README.md` 里目录结构图、"校验器"章节、发布流程图等明确写了平铺路径
（`src/content/posts/<slug>.md`）的几处，同步改成
`src/content/posts/YYYY-MM/<slug>.md`，避免文档和实际结构对不上。

## 4. 组件划分

| 文件 | 改动 |
|---|---|
| `pipeline/main.py` | 新增 `_all_posts()`、`post_path()`；`reconcile()` 改用递归查找；`run_auto()` 写入点改落点 |
| `pipeline/seed.py` | `related_published()` 改用 `mn._all_posts()`；`process()` 写入点改落点，重写时清理旧月份的孤本 |
| `pipeline/drafts.py` | `run_drafts()` 写入点改落点（月份取运行当天，不读 `fm['date']`）；新增 `import main as mn` |
| `pipeline/routinerun.py` | `run()` 写入点改落点；新增 `import main as mn` |
| `pipeline/repair.py` | 扫描改递归；新增 `import main as mn` |
| `src/content.config.ts` | `glob()` loader 加 `generateId`，剥离目录前缀 |
| `src/content/posts/2026-08/*.md` | 17 篇现有文章 `git mv` 迁入 |
| `README.md` | 同步平铺路径描述为按年月归档 |
| `pipeline/test_pipeline.py` | 新增自检 + 更新既有测试的写入落点断言（见验证方式） |

## 5. 验证方式

- `python pipeline/test_pipeline.py` 全绿，新增自检覆盖：
  - `reconcile()` 能在月份子目录里找到文章并正确对账（不会误判"文件没了"
    而销账）
  - 四个写入点落在按"运行当天"算出的正确月份子目录
  - `related_published()` 能找到跨月份文章的标题
  - `seed.process()` 重跑已发布文章、月份变化时，旧月份文件夹不留孤本
  - 既有测试里断言"写入落点"的几处（`blog / 'src' / 'content' / 'posts' /
    f"{slug}.md"` 这类构造平铺路径的断言）改成按新落点断言；只是搭 fixture
    用的平铺路径不用动，因为递归 glob 天然也能扫到深度为 0 的文件
- `npm run build` 通过（先 `npm install`，`node_modules` 目前是空的），
  确认路由、系列匹配不受影响
- 迁移后人工检查：17 篇文章确实都在 `src/content/posts/2026-08/` 下，
  站点首页 / 文章详情页 / 系列页在构建产物里没有 404 或 id 不匹配的报错
