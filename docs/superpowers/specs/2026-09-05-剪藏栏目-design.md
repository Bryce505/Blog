# 剪藏栏目：公众号文章与 X 帖子上站 — 设计文档

日期：2026-09-05
状态：已评审（用户在对话中逐项确认四个取舍）
分支：`claude/content-aggregation-blog-j8284d`

## 1. 背景与目标

`Bryce505/Notes` 是一条已经在跑的剪藏流水线：手机上复制一条公众号文章或 X
帖子的链接、点一下桌面小组件，约 15 秒后就往两个地方各写一份 —— Notion
数据库一条记录，仓库里一份 Markdown。仓库里的形态是：

| 路径 | 内容 |
|---|---|
| `notes/YYYY-MM.md` | 公众号月度索引，一条一个 `##` 块，最新的在最上面 |
| `notes/x/YYYY-MM.md` | X 帖子月度索引，格式同上 |
| `archive/YYYY-MM/*.md` | 公众号全文快照 |
| `archive/x/YYYY-MM/*.md` | X 帖子全文快照 |

每条记录带 AI 产出的**摘要、关键词、洞见、阅读优先级、是否值得读**。到写这份
文档时，`notes/2026-08.md` 有 60 余条、`notes/x/2026-08.md` 有 12 条。

**这批内容目前只有作者本人看得到** —— 躺在一个笔记仓库和一个 Notion 库里，
没有可读的呈现。而它恰好是本站现有内容的补集：`src/content/posts/` 是自己写的
原创，剪藏是「读了别人什么、判断它值不值得读」。

**目标**：把两个来源的月度索引同步进本仓库，在 `/clips` 一页里按剪藏时间倒序
展示，读者能按来源与优先级筛选，点标题去原文、点快照去 Notes 仓库看全文。

## 2. 决策记录

| 决策项 | 结论 | 理由 |
|---|---|---|
| 数据来源 | **只读 `Bryce505/Notes` 仓库**，不接 Notion API | 用户决策。`data/index.json` 里每条都带 `notion_page_id` —— 两边装的是同一批内容，Notion 只是同一条流水线的另一个目的地。再接一遍等于多一份密钥、多一条会漂移的真相，换不来任何本站需要的信息。仓库是公开的，内置 `GITHUB_TOKEN` 就能 checkout，零 secret |
| 全文快照 | **不镜像，只链回 Notes 仓库** | 用户决策。公众号正文是别人的版权内容，转载到公网站点有风险；且 `archive/2026-08/` 一个月就几百 KB，全量镜像会持续撑大本仓库。本站展示的是 AI 摘要与洞见（本仓库自己产出的判断），正文留在原处 |
| 页面组织 | **单页 `/clips` 合并流** + 来源与优先级筛选，月份做分组小标题 | 用户决策。两个来源的条目结构完全相同，分成两个栏目页只会让导航变长、让「这个月我读了什么」被切成两半 |
| 融入程度 | **独立栏目，不进 RSS / 标签页 / 归档 / `published.json`** | 用户决策。剪藏是「别人的文章 + AI 摘要」，和 `posts/` 里的原创不是一类东西。混进 RSS 与标签页会稀释原创内容，也会让账本与校验器的语义变复杂 |
| md → 结构化数据放哪 | **同步时用 Python 解析成 `src/data/clips.json`**，Astro 只读 JSON | 见下一节 |
| 解析失败怎么办 | **抛错让 workflow 红**，不静默降级 | 与 `verify.py`、`reports.astro` 同一条原则：拦不住就别上线。静默降级的后果是站上出现一排缺字段的空卡片，而没有任何人会收到通知 |

## 3. 为什么解析器落在 Python 而不是 Astro

本仓库已有一条几乎同形的通道：`sync-reports.yml` 把 `zotero-arxiv-daily` 的
HTML 周报镜像进 `public/reports/`，`reports.astro` 在构建期从每份 HTML 里抽
两个字段（`<title>` 与「覆盖期」），抽不到就让构建失败。

**这次没有照抄那条路**，理由是字段数量与可选性完全不是一个量级：

- 周报抽 2 个字段，两个都必有。剪藏要从正文里抽 10 个字段，其中 `insights`、`verdict`、
  `snapshot`、`publishedAt` 都**允许缺失** —— 实测样本里「Karpathy课程推广帖」
  就没有洞见（AI 判定这条帖子没有实质观点）
- 有分支就要测。本仓库的自检体系是 `pipeline/test_pipeline.py`（零依赖、
  `assert` + 文件底部 runner，152 项），只覆盖 Python。解析器写进 `.astro`
  文件的话，「缺洞见」「缺快照」「上游多加一行」这些边界只能靠真实数据碰运气

所以：**同步 workflow 里跑 `pipeline/clips.py`，产出 `src/data/clips.json`**，
站点侧一句 `import clips from '../data/clips.json'` 读进来，构建期零解析逻辑。

顺带的三个好处：产物是一个可 diff 的 JSON（上游改了什么，看提交 diff 就知道）；
构建不依赖网络，离线可复现；上游格式变动在**同步时**就炸，不会拖到构建期。

考虑过但放弃的第三条路：Astro content collection 自定义 loader 直接读 md。
它同时背着「解析器在 JS 里测不到」和「构建期才炸」两个问题，比直接镜像 md 更绕。

### 为什么不做成 content collection

`src/content/series.json` 走的是 `file()` loader + zod schema，这次刻意没照抄。
分界线是**这份 JSON 有没有人手写**：

- `series.json` 是手写的，zod 挡的就是手滑 —— 打错一个文章 id、少一个字段
- `clips.json` 是 `clips.py` 生成的，而该抛的错在生成时已经抛过一遍，且那一遍
  有自检覆盖。再用 zod 抄一份同样的规则到 TypeScript 里，等于同一条约束养两个
  版本，改上游格式时必然只改一边

所以放 `src/data/`（不是 `src/content/`）：那个目录下的东西都是 collection，
混一个不是 collection 的 JSON 进去，下一个人得读完 `content.config.ts` 才敢确定
它不是。同理**不给条目编 `id`** —— 没有任何东西按 id 索引单条剪藏，Astro 的
`map()` 也不需要 key，编一个出来就是一个没人用、却要保证稳定的字段。

## 4. 数据流

```
Bryce505/Notes（公开仓库）
  notes/YYYY-MM.md          公众号月度索引
  notes/x/YYYY-MM.md        X 月度索引
        │
        │  .github/workflows/sync-clips.yml
        │    定时（每天一次，避开整点）/ workflow_dispatch
        │    ① actions/checkout 上游到 .clips/
        │    ② python pipeline/clips.py --notes .clips --out src/data/clips.json
        │    ③ 有 diff 才提交
        ▼
  src/data/clips.json        唯一产物，进仓库
        │
        │  clips.astro 里一句 import
        ▼
  src/pages/clips.astro  →  https://bryce505.github.io/Blog/clips
```

`deploy.yml` 的 `workflow_run` 触发列表**必须加 `sync-clips`**。GitHub 的防递归
安全规则：workflow 用内置 `GITHUB_TOKEN` 推的提交不触发其他 workflow 的 `push`
事件 —— 漏了这条，同步进来的剪藏会永远躺在仓库里不上线。这个坑本仓库在
`publish` 与 `sync-reports` 上各踩过一次，README 的「架构总览」有记录。

## 5. 数据结构

`src/data/clips.json` 是一个数组，每条一个剪藏。**按剪藏时间倒序**，跨来源
合并排序 —— 页面直接按数组顺序渲染，不在构建期再排一次（两处排序必然漂移）。

```json
[
  {
    "source": "x",
    "month": "2026-08",
    "title": "Agent = Model + Harness：六层实战手册",
    "clippedAt": "2026-08-28 18:16",
    "publishedAt": "2026-08-28",
    "priority": "高",
    "keywords": ["Harness", "Agent工程", "六层架构"],
    "summary": "文章提出 Agent = Model + Harness 的核心观点……",
    "insights": ["只改 Harness 不换模型，收益可超过模型升级……"],
    "verdict": "信息密度高，提供完整的六层架构……",
    "url": "https://x.com/shao__meng/status/2093228362965651665",
    "snapshot": "https://github.com/Bryce505/Notes/blob/master/archive/x/2026-08/Agent_%3D_Model…md"
  }
]
```

### 字段来源与缺失处理

上游格式的唯一真相是 `Bryce505/Notes` 的 `src/clipper/md_writer.py::render_entry`。

| 字段 | 从哪抽 | 缺了怎么办 |
|---|---|---|
| `source` | 由文件路径定：`notes/x/` → `x`，`notes/` → `weixin` | — |
| `month` | 文件名 `YYYY-MM` | — |
| `title` | `## ` 标题行 | **抛错** |
| `clippedAt` | `- **剪藏**：YYYY-MM-DD HH:MM ｜ **发布**：…` 的前半 | **抛错** |
| `publishedAt` | 同一行的后半；上游写 `未知` 时留空 | 空串 |
| `priority` | `- **优先级**：高 ｜ **状态**：未读` | **抛错** |
| `keywords` | `- **关键词**：a / b / c`；上游写 `无` 时留空 | 空数组 |
| `summary` | `- **摘要**：…` | 空串 |
| `insights` | `- **洞见**：` 之后缩进两格的 `- ` 列表 | 空数组 |
| `verdict` | `- **是否值得读**：…` | 空串 |
| `url` | `- **链接**：[原文](URL) ｜ …` | **抛错** |
| `snapshot` | 同一行的 `[全文快照](相对路径)`，还原成 Notes 仓库 blob URL | 空串 |

**四个必填字段抛错，其余给空值**，界线是「缺了这一条，这张卡片还成不成立」：

- `title` / `url` 缺了就是一张点不开的无名卡片
- `clippedAt` 缺了排不进时间流
- `priority` 缺了或不是 `高/中/低` 三者之一 —— 页面顶部的优先级筛选按这三个值
  分档，一个档外的值会让这条卡片**被每一个筛选条件都藏起来**，等于内容凭空消失。
  上游 `ai.py` 已经保证只产出这三个值（`if priority not in ("高","中","低")`
  兜底成「中」），所以出现第四种值只可能意味着格式变了

另加一条整体检查：**一份月度文件解析出 0 条就抛错**。上游哪天把 `##` 换成 `###`，
逐条检查一条都不会触发（因为根本没有条目进入循环），站上会静默变成一个空栏目。

### 快照路径怎么还原

上游写的是**相对于索引文件所在目录**的 percent-encoded 路径：

- 公众号（索引在 `notes/`）：`../archive/2026-08/xxx.md`
- X（索引在 `notes/x/`）：`../../archive/x/2026-08/xxx.md`

还原成仓库相对路径用 `posixpath.normpath(posixpath.join(索引目录, 相对路径))`，
再拼 `https://github.com/Bryce505/Notes/blob/master/<路径>`。路径里的中文已经是
上游编码好的，**不再动它** —— 二次编码会把 `%E4%B8%87` 变成 `%25E4%25B8%2587`，
链接直接死掉。

## 6. 页面设计

`/clips`，视觉稿见 `design/Clips.dc.html`（Claude Design 画布）。

**页头**：栏目名 + 一段说明，必须讲清三件事 —— 这是什么（读到的公众号文章与 X
帖子）、摘要与洞见是 AI 产出的（不是作者本人的判断）、正文不在本站（点链接去
原文或快照）。第三件尤其重要：读者点进来看到一堆标题，得知道正文在别处。

**工具条**：来源（全部 / 公众号 / X）与优先级（全部 / 高 / 中 / 低）两组按钮，
外加一个实时条数。纯静态站点，用一小段内联 JS 切 `hidden` 属性实现；**无 JS 时
全部条目正常显示**（渐进增强 —— 筛选是便利，不是内容的前提）。

**条目卡片**（从上到下）：

1. 来源徽标（公众号 / X）+ 优先级徽标（高用 `--accent`、中用 `--muted`、低更淡）
2. 标题，链原文，`target="_blank" rel="noopener"`
3. 元信息行：剪藏日期 · 发布日期 · 「全文快照 ↗」
4. 关键词 chips
5. 摘要（正文块，受 `--measure` 约束）
6. 洞见列表，左侧一条 accent 竖线（复用 `.callout` 的视觉语言）
7. 「是否值得读」，弱化成 muted 小字 —— 它是判断不是内容

**月份分组**：`## 2026年08月` 小标题 + 该月条数。分组只按 `month` 字段切，不按
来源切。

**空态**：`clips.json` 是**提交进仓库的产物**，页面直接 import —— 文件不存在
就构建失败，这是要的（缺了产物的构建不该悄悄上线一个空栏目）。数组为空（上游
一条剪藏都还没有）时显示「还没有同步到剪藏」。

## 7. 顺带修：导航在手机上溢出

`Header.astro` 的 `nav` 是 `display:flex; gap:22px` 且**没有换行与滚动**。实测
现有 6 条导航在 375px 宽的手机上已经溢出（内容宽约 456px，可用约 343px）。这次
加第 7 条「剪藏」会让它更糟。

按 `CLAUDE.md`「顺手发现的无关 bug，小到一两行就在本分支顺带修，并在日志里单独
注明」处理：给 nav 加 `flex-wrap: wrap` + 窄屏下 `row-gap`，让它折行而不是溢出。
不做汉堡菜单 —— 7 条中文导航折成两行完全可读，一个折叠菜单要引入 JS 状态、
焦点管理与无障碍属性，为这点收益不值得。

## 8. 验证方式

| 层 | 怎么验 |
|---|---|
| 解析器 | `pipeline/test_pipeline.py` 补自检，fixture 放 `pipeline/fixtures/clips-weixin.md` 与 `clips-x.md`。覆盖：正常解析全字段、可选字段缺失、四个必填字段各自缺失都抛错、0 条抛错、快照路径还原（含 X 多退一层）、跨来源按剪藏时间倒序、priority 档外值抛错 |
| 站点 | `npm run build` 通过，页面在真实数据下渲染正常 |
| 端到端 | 分支上拿真实的 `Bryce505/Notes` 数据实跑一次 `pipeline/clips.py`，核对条数与随机抽查几条的字段 |

## 9. 本次不做

- 不镜像全文快照，不做站内阅读页
- 不进 RSS / 标签页 / 归档页 / 搜索 / `published.json`
- 不接 Notion API
- 不给剪藏做全文搜索或关键词聚合页（先看这一页有没有人读）
- 不碰 `pipeline/` 现有任何文件的行为（`clips.py` 是新增的独立模块，不进
  `main.py` 的五步流程，也不经过 `verify.py` —— 剪藏不是 AI 改写的产物，
  没有「篡改数据」这个风险面）
