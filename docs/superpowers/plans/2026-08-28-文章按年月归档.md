**Goal:** 把 `src/content/posts/` 从平铺目录改成按 `YYYY-MM` 分子文件夹，流水线的写入/对账逻辑同步感知新结构，站点路由与系列匹配不受影响。

**Architecture:** `pipeline/main.py` 新增两个共享函数（`_all_posts()` 递归查找、`post_path()` 计算落点），替换 5 个模块里各自的平铺 glob/拼路径逻辑；`src/content.config.ts` 的 `glob()` loader 加 `generateId`，让文章 id 继续只取文件名；17 篇现有文章一次性 `git mv` 迁移。

**Tech Stack:** Python 3（流水线，assert + 文件底部 runner，无测试框架）、Astro 7 content layer API（`astro/loaders` 的 `glob()`）、`github-slugger`（新增依赖，复刻 Astro 内部对单段路径的 id 处理）。

**Spec:** `docs/superpowers/specs/2026-08-28-文章按年月归档-design.md`

## Global Constraints

- 月份文件夹命名：`YYYY-MM`（如 `2026-08`）
- 文章文件名（slug）不变，不加日期前缀
- 月份文件夹的取值**不读 frontmatter 的 `date` 字段**，四个写入点各自用运行当天（`dt.date.today()`）计算月份
- `entry.id` 必须和现在的 slug 完全一致（文件名去扩展名，经 `github-slugger` 处理）——`[...slug].astro` 拿它当 URL，`series.json` 拿它匹配文章
- 新增/修改流水线模块间的 import 只能沿用现有模式：`main.py` 对叶子通道（`drafts`/`repair`/`routinerun`/`seed`/`manual`）一律函数体内延迟 import；叶子通道在自己的模块顶层 `import main as mn`。反过来会循环引用
- 合并前提：`python pipeline/test_pipeline.py` 全绿、`npm run build` 通过
- `pipeline/test_pipeline.py` 走 assert + 文件底部 runner 风格（`def test_*()`，无 pytest/框架依赖），不引入新的测试写法

```python
def _post(blog, slug, month=None, **fm):
    """在 posts/ 造一篇文章，frontmatter 只写给定字段。month 给定时落在对应
    月份子目录，用来测「文章在月份文件夹里」的场景；不给就还是平铺（兼容
    既有调用，也覆盖「迁移前遗留平铺文件」这个场景）。"""
    d = Path(blog) / 'src' / 'content' / 'posts'
    if month:
        d = d / month
    d.mkdir(parents=True, exist_ok=True)
    lines = ['---']
    for k, v in fm.items():
        if isinstance(v, list):
            lines.append(f'{k}:')
            lines += [f'  - "{x}"' for x in v]
        elif isinstance(v, bool):
            lines.append(f'{k}: {"true" if v else "false"}')
        else:
            lines.append(f'{k}: "{v}"')
    lines += ['---', '', '正文']
    (d / f'{slug}.md').write_text('\n'.join(lines), encoding='utf-8')
```

```python
def _all_posts(posts_dir):
    """slug -> Path，递归扫全部月份子目录（含可能残留的平铺文件）。

    分月份子目录后 reconcile()/related_published() 都不能再假设 posts/
    是平铺的，一处递归扫描给它们共用，避免各自实现一遍、之后行为漂移。
    """
    posts_dir = Path(posts_dir)
    return {p.stem: p for p in sorted(posts_dir.glob('**/*.md'))} if posts_dir.is_dir() else {}


def post_path(posts_dir, slug, month):
    """新文章该落在哪：posts_dir/month/slug.md。

    month 由调用方按「这次运行的当天」传入，不在这里读 frontmatter 的
    date 字段——date 允许回溯（drafts.py 的手动投稿通道），按 date 归档
    会把刚落地的稿子塞进旧文件夹，找不到刚落地的东西。
    """
    return Path(posts_dir) / month / f'{slug}.md'
```

## Task 8: Astro `generateId`，保住现有文章 URL 和 `series.json` 匹配

**Files:**
- Modify: `package.json`（新增依赖 `github-slugger`）
- Modify: `src/content.config.ts:1-9`

**Interfaces:**
- Consumes：Task 7 迁移后的真实嵌套目录（用于本任务末尾的 `npm run build` 验证）
- Produces：`entry.id` 对每篇文章保持跟迁移前完全一致的值（文件名去扩展名，经 `github-slugger` 处理，不含目录路径）

**背景**（已在设计阶段验证，见下方"已核实的事实"）：Astro 的 `glob()` loader 默认会把子目录路径编进 `id`；不做处理的话，`src/pages/posts/[...slug].astro` 用 `entry.id` 当 URL、`src/lib/series.ts` 用 `entry.id` 匹配 `series.json`，两处都会被这次迁移打断。

**已核实的事实**：Astro 非 legacy 模式的默认 `generateId` 对单段路径（没有目录前缀时）会先做 `githubSlug()` 处理再当 id——不是原样使用文件名。用当前 17 篇文章的文件名实测过（`node -e "require('github-slugger').slug(...)"`），16 篇结果跟文件名完全一样，**唯一例外是 `HCP鉴定与定量` → `hcp鉴定与定量`（大写字母被转小写）**。这意味着自定义 `generateId` 必须复刻同一步 `githubSlug()` 处理，不能只是简单地取文件名——否则这一篇文章的 URL 会被这次改动悄悄改掉。
