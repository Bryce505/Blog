# 2026-09-05　文献周报栏目：镜像另一个仓库的 HTML 周报，正文不经手

## 背景

`Bryce505/zotero-arxiv-daily` 每周五自动产出一期 CMC 文献周报，落在那个仓库的
`reports/<年>/` 下，一期一份 HTML 加一份同内容的 md。目前站上一篇都看不到：
读者要看周报，得去 GitHub 仓库里点开文件 —— 而 GitHub 对 `.html` 的处理是
显示源码，不是渲染页面，等于根本读不了。

三期已经积在那儿（2026-08-W3 / 08-W4 / 09-W1，14 / 18 / 16 篇文献），每周还
会多一期。

## 实现

**周报正文一个字节都不经过 Astro。** 上游那份 HTML 是完整自洽的文档：自带
`<style>`（侧边目录、卡片、深色模式）、零脚本、零外链资源。三种呈现方式里选了
最省的一种：

| 方案 | 为什么不选 |
|---|---|
| 剥掉 `<head>` 把 `<body>` 塞进本站布局 | 它的 CSS 直接选 `body` / `main` / `h1` / `.card`，与 `global.css` 必然打架，得逐条改写或加作用域；而上游每期结构还在变，改写一次不等于以后都对 |
| iframe 套进站点版式 | 双滚动条、高度算不准，为了一条页眉不值 |
| **拷进 `public/`，Astro 原样输出** ✓ | `public/reports/2026/2026-09-W1.html` 直接就是 `/Blog/reports/2026/2026-09-W1.html`，呈现层零代码、零样式冲突，周报自带的目录与深色模式完整保留 |

代价是点开周报就离开了站点版式，所以索引页的链接用 `target="_blank"` 新标签
打开 —— 不注入返回链接，那是在改上游内容。

**同步用「先删再拷」的镜像语义，不做增量。**

```bash
rm -rf public/reports
cp -r .reports/reports public/reports
find public/reports -type f ! -name '*.html' -delete
```

只做增量拷贝的话，上游撤下或改名一期，站上会留下一个再没人维护的幽灵页面 ——
而且没有任何东西会发现。先删再拷则 `public/reports` 永远等于上游 `reports/`
的 html 子集。上游若把 `reports/` 整个挪走，这里 `cp` 会直接失败让 Actions
红一条，而不是静默提交一个空目录把整栏抹掉。

**为什么是独立 workflow，不塞进 `publish.yml`。** 塞进去能省一个文件、复用
现成的提交与部署触发，但会把「同步别人仓库的成稿」和「AI 整理笔记发文章」两个
毫不相干的失败域绑在一起：发文那步挂了（模型超时、校验器拦下、Drive 取图失败
都会），周报就跟着同步不了。周报一周才一期，漏一次就是站上少一周。

配套必须改 `deploy.yml` 的 `workflow_run: workflows: [publish, sync-reports]`。
不加这行，同步提交永远不会上线 —— workflow 用内置 `GITHUB_TOKEN` 推的提交不
触发其他 workflow 的 `push` 事件，这个坑 `deploy.yml` 里本来就有注释记着。

**cron 排了主备两条**（周五 UTC 13:30，上游 12:00 出稿后 90 分钟；周六 UTC
09:40 备份）。理由见 `2026-08-27-定时任务整点排队延迟.md`：本仓库的 schedule
实测会整天不触发。同步是幂等的，没更新就什么都不提交，多跑一条零成本。

**索引页抽不到元数据就让构建失败。** 索引页从每份 HTML 里正则抽 `<title>` 和
摘要行。摘要行特意锚定「覆盖期」三个字，而不是取第一个 `class="meta"`：这个类
在页面里有几十处（每篇文献下面也是它），按「第一个」取的话，上游哪天在标题下
多插一行，索引页就会把某篇文献的作者当成周报的覆盖期显示出来 —— 错得像对的。

抽不到就 `throw`，和系列栏目的三条硬规矩同一个思路：静默降级的后果是站上出现
一排没有标题的空卡片，而没有任何人会收到通知。代价是上游改一次 HTML 结构会
连带把整站构建卡住（含当晚的文章发布），这是知情的取舍 —— 错误信息里写明了
该去看哪个目录、以及不要把校验删掉。

**目录不存在则是空态，不是报错。** 只有「同步从没跑过」或「有人手删了」会走到
这里，而真正的同步故障在 workflow 里就断了。让 `readdirSync` 抛一串 ENOENT
把构建搞挂，对不上任何真实故障。

**没做的事**：不建 content collection（周报不是 markdown，不参与标签/归档/RSS
/系列）、不写 Astro 路由端点（`public/` 原样输出已经够）、不收 md 与月报（md
是同一份内容的另一种格式；月报目前只有 md，要收得另起一条渲染通道）。

## 验证

**构建**：`npm run build` 45 → 46 页（新增 `/reports/index.html`）。
`python pipeline/test_pipeline.py` **152/152 通过**（本次不动流水线，此项用于
确认没有误伤）。

**产出比对**：`dist/reports/2026/` 三份 HTML 与上游仓库对应文件 `cmp` **逐字节
一致** —— 确认「正文不经手」不是说法而是事实。

**两条硬校验逐条实测**（造错后还原，`cmp` 确认与上游一致，无残留）：

| 造的错 | 实测结果 |
|---|---|
| 把 `class="meta">覆盖期` 改成 `本期概况` | 构建失败，**exit code 1**，报错点名文件 `2026/2026-09-W1.html` |
| 删掉 `<title>` 整行 | 同上，同一条报错 |
| 整个 `public/reports` 目录移走 | 构建成功（exit 0），页面显示「还没有同步到周报」 |

exit code 是专门确认的：若 Astro 只打印 `[ERROR]` 却仍以 0 退出，坏数据会跟着
部署上线，硬校验就形同虚设。

**同步逻辑本地实跑**（把上游 clone 软链成 `.reports`，跑 workflow 里同一组
命令）：

- 幂等：已同步过再跑一次，文件清单不变，仍是 3 份 html
- 镜像语义：手工塞一个 `2026-07-W9.html` 假页面进去，同步后被清掉
- 只收 html：同步后 `find -name '*.md'` 为 0（上游 3 份 md + 1 份月报都没进来）

`sync-reports.yml` 与 `deploy.yml` 都过了 YAML 解析，触发配置逐项核对无误。

**浏览器实测**（Chromium 1280×900，深浅两种主题）：

- `/Blog/reports`、三份周报页面全部 HTTP 200；首页导航「文献周报」链接指向
  `/Blog/reports`
- 索引页三张卡片按时间倒序（09-W1 / 08-W4 / 08-W3），覆盖期与篇数显示正确
- 周报页面渲染完整：左侧目录、锚点、青色主题、卡片版式全部保留，与站点样式零
  冲突
- 深色模式下索引页与站点其余部分一致

控制台报错只有 `fonts.googleapis.com` 被本沙箱代理挡下这一类，改动前就有，与本
次无关。

**实测修正**：索引页说明文字里的行内链接两侧没有空格，渲染成「由zotero-arxiv-daily
自动生成」—— JSX 会把标签前后的换行空白吃掉。把那句话并成一行解决。
