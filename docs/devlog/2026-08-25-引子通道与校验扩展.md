# 2026-08-25　引子通道（加减法）、校验器扩展、人工投稿通道

## 背景

自动通道是「多篇笔记打散重组」，产出拼接感很强：几篇笔记各讲各的，模型
只能按顺序摆，覆盖面广但每节浅尝辄止 —— 实测那篇 8 篇笔记合成的《治疗性
单抗质量属性与表征方法》就是这个毛病，读起来像目录不像文章。

先试了「单篇笔记做引子让模型扩写」，三篇样稿结构明显好转（成药性那篇
4,043 → 7,724 字符，补出的「常见误区与边界条件」一整节原笔记完全没有，
且纯定性、零编造数字）。据此确定取材方式改为引子通道，并按笔记完整度
分加减法两种模式。

新的风险是模型可能编出处。「有没有幻觉」没法用正则判定，得换个形式解决。

## 实现

**把不可判定的问题转成可判定的。** 要求模型为每处扩展写 `[依据 N]` 标注，
并在文末列出可核验的来源（知识库路径或 DOI）。机器逐条回原文核对：路径
必须真实存在、引用要点必须在那篇笔记里找得到、DOI 必须在输入材料里出现过。
编造的出处在这三处必然露馅。

引用要点用**字符二元组重合度**（阈值 0.5）而不是全句匹配：模型转述是正常
的，逐字比对会把所有正常转述判成幻觉。中文没有空格分词，二元组是不引入
分词依赖的最省事代理。阈值刻意宽松 —— 这个检查要拦的是整条编造，不是做
相似度评分。

**加减法用篇幅比例做确定性判定**：减法 55%～95%，加法 105%～300%。缩到
一半以下说明删掉了不该删的，翻三倍以上是过度扩展。

**扩展素材优先从知识库取**：加法模式下把同三级标签的相关笔记（最多 6 篇、
每篇截 3000 字符）随提示词一起喂进去，模型只能引用这些片段里出现过的路径。
这样「来源」天然可核验，比让它凭记忆写文献可靠得多。

**关联文章的链接由流水线生成**，不让模型写：模型不知道站上已经发过什么，
让它写必然编 slug。

**通知三条出口互相独立**：日志随产出一起提交（翻历史不用翻 Actions 页面），
GitHub Issue 零配置且手机有推送，SMTP 配了才发。通知失败绝不能让流水线
失败 —— 文章已经落盘了，为了发不出去的通知把产出丢掉是本末倒置。

## 验证

自检 108 → 115 项，新增的七项覆盖：加减法模式判定、减法删过头被拦、加法
没写依据被拦、编造出处被拦、转述式引用要点放行、关联文章自动带链接、
随稿图片就地转换且原稿撤走。

引子通道的三篇实跑样稿在 `_review/` 下（HCP 鉴定与定量、光散射表征、
成药性评估），其中 HCP 那篇被校验器拦下 3 个模型自己补的数值 —— 红线
按预期生效。
