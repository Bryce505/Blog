# 2026-08-26　站内系列栏目：一组文章按指定顺序成串

## 背景

站上现有的两种归拢方式 —— 分类和标签 —— 都是**无序集合**。进了「03质量控制」
的文章彼此平级，读者看不出「这几篇是一条线，该按这个顺序读」。

而知识库里大量内容天然成串：ELISA 的 MRD 建立 → 稀释线性 → 平行性验证是一条
线，结构表征从早研到 BLA 是另一条。这些顺序信息在当前站点上完全丢失。

原始设想是在**流水线侧**做系列化选题：规定专题 → 从库里收集相关文档 →
制定发布计划 → 审核后按计划发布。放弃这条路，三个理由：

1. **校验器与「单篇引子」深度绑定。** 让模型规划多篇文章的大纲，意味着要为
   「大纲里每条论断」另建一套真实性核验，得改 `verify.py`。那是整条流水线的
   安全阀，为一个还没验证过价值的功能去动它，风险与收益不成比例。
2. **没有真实样本可参照。** 站上真正发布的只有 3 篇，`_review/` 还压着 9 篇
   待放行。没有一个跑通的系列，无从判断「AI 规划的系列大纲」好不好。
3. **呈现层能先把价值兑现。** 系列的读者价值（有序、有上下文、看得见全貌）
   全部落在呈现层。先手工攒出真系列观察效果，再决定要不要自动化选题。

## 实现

**系列数据放单文件，不放 frontmatter。** 两个方案都能表达归属，差别在顺序：
写进每篇文章的 `series` / `seriesOrder`，调一次次序要改 N 个文件，而且两篇
写了同一个序号没有任何东西会拦。放 `series.json` 则数组顺序**就是**阅读顺序，
不另设序号字段 —— 设了序号字段就有两个真相。代价是以后想让流水线自动挂系列
要多改一步，但那件事本来就还没到时候。

顺带的好处：文章 frontmatter 一个字段都不用加，两条产出通道
（`main.assemble_frontmatter`、`drafts.fill_defaults`）与 posts schema 全部不动，
流水线零风险。

**三条校验做成构建期抛错，不做静默降级。** 这是照搬校验器的思路 —— 拦不住
就别上线：

| 场景 | 若静默处理会怎样 |
|---|---|
| `post` 填的 id 不存在 | 打错一个字就变成页面上一条看不出错的灰「待发布」条目 |
| 一篇文章进了两个系列 | 文章页归属提示只有一处，显示哪个都是错的 |
| 一个 entry 同时写 `post` 和 `planned` | 意图不明，只能靠猜 |

第一条正是**「待发布条目必须显式写 `planned`」的唯一理由**：若允许「找不到
就当作待发布」，就再也分不清「我还没写」和「我打错了」。

**「第 N / M 篇」含待发布条目，上下篇跳过它们。** M 表达的是这个系列计划写
多少篇，与「发布计划」的定位一致；而待发布条目没有页面可链，所以上一篇/
下一篇要跳过去找最近的已发布条目。

**系列详情页用编号目录而不是文章卡片流。** 卡片流表达不出顺序，也放不下
「待发布」这种没有链接的条目。

**解析逻辑集中在 `src/lib/series.ts` 一处。** 三个页面各写一遍必然漂移，
而漂移的后果是同一篇文章在系列页和文章页显示出不同的序号。

## 验证

**构建**：15 → 17 页，`npm run build` 通过。`python pipeline/test_pipeline.py`
117/117 未退化（本次不动流水线，此项用于确认没有误伤）。

**三条硬校验逐条实测，全部让构建失败且报错文本准确指出问题**：

| 造的错 | 实际报错 |
|---|---|
| id 改成 `00基础-生物制品-单抗-打错了` | `系列「单抗表征方法」的第 1 条引用了不存在的文章 id「…」` |
| 同一篇再放进一个「重复测试」系列 | `文章「00基础-生物制品-单抗」同时属于系列「单抗表征方法」和「重复测试」` |
| 一个 entry 同时写 post 与 planned | `entries.1: entry 必须恰好有 post 或 planned 之一` |

**上下篇导航单独造数据实测**（当前唯一的真实系列只有 1 篇已发布，上下篇都是
空，不造数据就测不到）。临时建一个「第 1 篇已发布 / 第 2 条待发布 / 第 3 篇
已发布」的系列：

- 第 1 篇只出现「下一篇」，且**跳过中间的待发布条目**直接指向第 3 篇
- 第 3 篇只出现「上一篇」，指回第 1 篇
- 序号显示 1/3 与 3/3，而不是 1/2 与 2/2 —— 待发布条目确实计入总数

验完即撤，`git diff` 确认 `series.json` 无残留。

**浏览器实测**（Chromium，1280×900，深浅两种主题）：系列索引页、系列详情页、
系列内文章页三页均 HTTP 200；系列详情页 9 个站内链接全部可达无 404；文章页
meta 行显示「单抗表征方法　第 1 / 5 篇」且系列名可点回系列页；不属于任何系列
的文章页零影响（grep「本系列」为 0）。

控制台有两类报错，均与本次改动无关、改动前就有：`fonts.googleapis.com` 被本
沙箱代理挡了（站点回退到 CJK 字体栈），以及全站没有 favicon（`public/` 里
没放）。后者是个真实的小缺陷，但需要选图标，不在本分支范围内。
