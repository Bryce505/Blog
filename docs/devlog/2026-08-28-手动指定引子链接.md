# 2026-08-28　手动触发发布支持指定一篇笔记，不用等流水线随机挑

## 背景

用户反馈：手机 GitHub App 上能手动触发 `publish` workflow，但发布哪篇文章
是流水线自动挑的（`seed.candidates()` 按体量从大到小选），选中哪篇不受
人控制——想要的是能自己指定这次到底拿哪篇笔记发布。

头脑风暴时最初设计的方案偏重：新增 `--list-seeds`/`--list-drafts` 两个
命令列出候选，另开一个 `list.yml` workflow 把清单发到一个置顶 Issue 上，
供手机/网页浏览后再回来指定。方案讨论到一半，用户提出他本来就能直接在
私有的 `Obsidian-base` 仓库里翻目录找到想要的笔记、复制它的 GitHub 链接
（例如 `.../blob/master/Antibody-Engineering%2F抗体结构与功能.md` 这种
形式）——这条路径本身就是现成的「候选浏览」，不需要另造一套清单机制。
定稿方案因此整个砍掉了清单那一半，只留「链接指定」这一层。

## 变更

- 新增：`pipeline/main.py` 的 `resolve_seed_url()`，把 GitHub
  blob/raw/blame 链接解析成 vault 内的相对路径；裸路径原样返回
- 新增：`pipeline/main.py` argparse 的 `--seed-url` 参数，跟已有的
  `--seed <路径...>` 收拢到同一个 `seed_paths`，交给 `seed.run()`
- 修改：`.github/workflows/publish.yml` 的 `workflow_dispatch` 新增
  `seed_url` 文本输入；`mode: seed` 时填了就走 `--seed-url`，留空保持
  现状自动选
- 新增：`pipeline/test_pipeline.py` 5 条自检（标准链接解析、
  `?plain=1` 查询参数、`raw`/`blame` 视图、裸路径直通、无法解析时
  的兜底行为）
- 修改：`README.md`「手动触发一次发布」：开关表格从四个补到五个，新增
  小节讲怎么用链接指定笔记，并补一句「草稿转正」直接编辑文件、不需要
  新开关

## 实现

**改动范围比最初设计小很多，是因为一个已经存在的操作习惯替代了整套
新机制。** `--seed <路径>` 这条底层能力（`seed.py` 的 `run()`）本来就
支持显式指定笔记，一直没通的只是「手机/网页上怎么表达这个路径」。用户
已经会在 `Obsidian-base` 里翻文件、复制链接，剩下要做的只是把这个链接
解析成路径——不用再造一层"先列出候选、再选序号/文件名"的间接机制。

**链接解析放在 Python 侧一个纯函数里，不在 shell/yaml 里拼正则。**
`resolve_seed_url()` 好写单元测试、好维护边界情况（查询参数、
`raw`/`blame` 视图、解析失败的兜底），比在 `publish.yml` 的 `run:` 块里
用 `sed`/`grep` 处理这些情况更可靠。

**`SEED_URL` 展开不加引号转义。** 一开始想过 `ARGS="--seed-url
\"$SEED_URL\""` 这种写法防止路径带空格，但变量值里手动写的引号在后续
无引号展开时不会被 shell 重新解释成引用符——只会被当成字面字符传给
`argparse`，反而把多余的引号字符塞进了 URL 里。GitHub 链接本身是
percent-encoded、不含裸空格，跟其余分支保持一致的无引号展开写法更安全，
没有必要为一个不会发生的输入引入更复杂的引用规则。

**解析失败不在 `resolve_seed_url()` 里报错。** 拼错链接、笔记被移走，
函数原样把输入当路径返回，交给 `seed.run()` 已有的「找不到引子笔记：
{gone}」校验去拦——不会退回去自动选一篇顶替，也不用维护两套错误信息。

**「草稿转正」没有加任何新开关。** 已生成、还压着 `draft: true` 的候选
文章，本来就是编辑那个文件删掉 `draft: true` 一行就能放行（见「校验没过
怎么办」），这条路径跟用户描述的「直接在仓库里翻」是同一种操作习惯，
只是之前没写进「怎么选文章发布」这节，这次在文档里补上说明，没有改
任何代码。

**没有做的事：候选清单 / Issue 置顶机制。** 评估后跟用户确认过，这条
路径被「直接去 Obsidian-base 翻链接」完全替代，不需要，保留在这里
记一笔是避免以后有人重新提起时又要重新论证一遍。

  链接）确认——本地验证止于 `resolve_seed_url()` 的解析逻辑本身，以及
