# 2026-08-26　草稿位放行：`_review/` 目录取消

## 背景

放行一篇校验未通过的文章，人工要做五件机械事：改内容、删掉文件开头的
HTML 注释、去掉文件名的 `seed-` 前缀、把文件从 `_review/` 移到
`src/content/posts/`、往 `published.json` 补一条记账。

在 GitHub 网页和手机上，后四件基本做不动 —— 网页版没有「移动文件」按钮，
改名要在路径输入框里手打，`published.json` 要手写一段 JSON。`_review/`
里积到 9 篇的时候，这套流程实际上已经停摆了。

**根因不是步骤多，是同一个状态存在三个地方**：文件在哪个目录、文件开头的
HTML 注释、`published.json` 的记账。三份状态要人工手动对齐，漏一份就出事。
两次实测都出在这上面：

1. **HTML 注释在 GitHub 预览里整段不显示。** markdown 渲染器吃掉
   `<!-- -->`，人打开 `_review/seed-hcp鉴定与定量.md` 只看得到正文，
   根本不知道哪几项没过，得点 Code 或 Raw 才看得见。用户当场问的就是
   「顶部说明注释是指 title 那块内容？」—— 他压根没看见那段注释存在。
2. **master 上真发生过一次漏记账。** `HCP鉴定与定量` 手工搬进 `posts/`
   并已上线，`published.json` 里没有对应记录。引子通道按 `seed` 字段
   去重，那篇笔记因此仍算「没用过」，当晚 21:00 的定时任务会重新挑中它、
   再烧一次 DeepSeek、覆盖已发布的文章。这个 bug 是这次改动前一天成真的。

顺带查出一条同源的隐患：`published.json` 用 `primaryTag` 做 key，而同一
三级标签下会有多篇文章（ELISA 与 HCP鉴定与定量 的 `primaryTag` 完全
相同），两篇都记账时后写的会静默覆盖先写的。

## 变更

- 新增：`main.reconcile()` —— 每次运行开头把账本和 `src/content/posts/`
  对一次账，缺的回填、文件没了的销账
- 新增：`src/lib/posts.ts` 的 `listPosts()` —— 全站唯一的文章入口，
  草稿过滤只在这一处
- 新增：自检 `test_site_never_reads_posts_collection_directly` —— grep
  全站，`listPosts()` 之外出现裸 `getCollection('posts')` 就失败
- 修改：`published.json` 改用 slug 做 key，记录里补 `tag` 字段
- 修改：`assemble_frontmatter()` 支持草稿位，未过校验时输出
  `draft: true` + `reviewNotes`
- 修改：`seed.process()` / `run_auto()` 统一写 `posts/`，过与不过只差
  frontmatter 那一行
- 修改：`pick_next()` 按 tag 反查账本；没有 `source_hash` 的回填记录
  一律当作已发布，不重发
- 修改：`content.config.ts` 加 `draft` / `reviewNotes` 两个字段
- 修改：`verify.selection()` 的输入排除文章自己的记录
- 删除：`_review/` 目录、`seed.pending_review()`、`run_auto` 里按
  `_review/` 算的 skip 集合、`candidates()` 的 `pending` 参数

## 实现

**状态收敛成一处。** 过与不过都写 `src/content/posts/<slug>.md`，只差
frontmatter 里一行 `draft: true`。放行 = 删那一行；退稿 = 删文件；记账
自动。人只动文件本身，没有第二处状态要同步。

**`reviewNotes` 用 YAML 而不是 HTML 注释**，直接来自上面第 1 条实测 ——
选载体的唯一理由就是「GitHub 预览里看得见」。

**草稿位放 frontmatter 最前面**：打开文件第一眼就是「这是草稿」和为什么。

**评估过但否掉的两个方案：**

| 方案 | 放行动作 | 否掉的原因 |
|---|---|---|
| 文件名 `<slug>.draft.md` + Astro glob 负向匹配 | 改文件名 | 站点侧零改动、泄漏不可能，但改名正好卡在手机上最难做的那一步 |
| 保留 `_review/` + `--approve` 命令或 Actions 按钮 | 跑一次 CI | 还是得开终端或等 CI；且是造个机器人去干 `git mv` 的活，多一层机器多一层出错 |

**草稿不许漏上线，靠自检守。** 草稿和正式文章同住一个目录，全站 10 处
`getCollection('posts')` 逐处加过滤迟早漏一处，漏一处就是未审内容上线。
收敛成 `listPosts()` 一处，再加一条 grep 自检把「别处不许裸调」钉死。
这条按本仓库「校验器是安全阀」的规矩加 —— 靠人记住不算安全阀。

**回填记录刻意不带 `source_hash`。** 回填时拿不到 vault 算不出哈希，
于是把 `pick_next` 改成「没有哈希就当已发布」。这不只是妥协，也是更对的
语义：人工放行过的文章不该因为源笔记改了个错别字就被悄悄重写一遍。

**`verify.selection()` 的输入排除文章自己。** 草稿现在也进账本，不排除
自己的话，`--seed` 显式重跑同一篇会被「选材重复」挡住 —— 而那条规则拦的
是「另一篇文章已经占用了这个引子」，不是自己覆盖自己。校验规则一条没放宽，
只是把输入喂对。

## 验证

**自检 118 → 128 项，全绿。** 新增的 10 项覆盖：

- 手工搬进 `posts/` 的文章被自动回填（就是 master 上那个真 bug 的回归测试）
- 删文件后记录被销账
- 旧的 tag-key 账本迁移到 slug-key 且不丢 `source_hash`
- 同 `primaryTag` 的两篇文章不再互相覆盖
- 回填记录不被重发
- 校验未过时落 `posts/` 且带 `draft: true`、`reviewNotes` 是 YAML、
  frontmatter 在文件最开头、正文里没有 HTML 注释
- 草稿也记账，重跑自动选材不会再挑中同一篇
- 相关阅读跳过草稿（草稿没有页面，链过去是死链）
- 显式重跑自己的草稿不算「选材重复」
- 全站没有绕过 `listPosts()` 的裸 `getCollection('posts')`

**`npm run build` 通过，23 个页面，9 篇草稿零泄漏。** 逐项核对了构建
产物：`dist/posts/` 只有 5 篇正式文章；9 个草稿 slug 在整个 `dist/` 里
grep 结果都是 0；`rss.xml` 只有 1 条；`sitemap-0.xml` 里 5 条全是正式文章。

**实测了放行动作本身。** 对光散射那篇执行 `sed -i '/^draft: true$/d'`
（等价于人在 GitHub 网页上删掉那一行）→ 重新构建 → 该文章出现在
`dist/posts/` 和 `rss.xml` 里，页面数 23 → 26；再跑一次 `load_published()`，
账本里那条记录的 `draft` 字段自动销掉。整个过程没有改名、没有移文件、
没有手写 JSON。验证完已还原成草稿 —— 内容该由作者自己过目。

**在真实仓库上跑了一次对账**：14 条记录，其中 9 条草稿。`HCP鉴定与定量`
被自动收编并带上了正确的 `seed` 路径（今晚的定时任务不会再重跑它），
3 篇 `primaryTag` 同为 `03质量控制/残留/HCP` 的文章各自独立、互不覆盖。

## 存量 9 篇的状态

全部转成草稿迁进 `posts/`，等人工过目。其中 3 篇生成时校验全过
（成药性评估、光散射表征、ELISA 稀释线性），`reviewNotes` 写的是
「生成时校验全部通过，仅差人工过目」—— 删掉 `draft: true` 即可发布。
另外 6 篇的 `reviewNotes` 里逐条列着原来的问题。
