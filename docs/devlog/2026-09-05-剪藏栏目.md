# 2026-09-05　剪藏栏目：把公众号文章与 X 帖子的月度索引接上站

## 背景

`Bryce505/Notes` 是一条已经在跑的剪藏流水线：手机上复制一条公众号文章或 X
帖子的链接、点一下桌面小组件，约 15 秒后 Notion 里出现一条带 AI 摘要、关键词、
洞见与阅读优先级的记录，仓库里同时留一份 Markdown 归档。

**这批内容之前只有我自己看得到** —— 躺在一个笔记仓库和一个 Notion 库里，没有
可读的呈现。到动手时上游已经攒了 68 条（`notes/2026-08.md` 51 条、
`notes/2026-09.md` 2 条、`notes/x/2026-08.md` 15 条）。

它恰好是本站现有内容的补集：`src/content/posts/` 是自己写的原创，剪藏是「读了
别人什么、判断它值不值得读」。

## 实现

### 只取索引，不镜像正文

上游 `archive/` 里是公众号文章的全文快照。不镜像有两个理由：那是别人的版权内容，
转载到公网站点有风险；而且 `archive/2026-08/` 一个月就几百 KB，全量镜像会持续
撑大本仓库。站上展示摘要与洞见（自己这边产出的判断），正文链回上游。

### 解析器落在 Python 而不是 Astro

本仓库已有一条几乎同形的通道：`sync-reports.yml` 镜像周报 HTML，`reports.astro`
在构建期抽两个字段，抽不到就让构建失败。**这次没有照抄**，因为字段数量与可选性
不是一个量级：周报抽 2 个字段且都必有，剪藏要从正文里抽 10 个字段，其中
`insights` / `verdict` / `snapshot` / `publishedAt` 都允许缺失（实测 68 条里有
2 条没有洞见 —— AI 判定那两条帖子没有实质观点）。

有分支就要测，而本仓库的自检体系只覆盖 Python。放弃的第三条路是 Astro 自定义
loader 直接读 md：它同时背着「解析器在 JS 里测不到」和「构建期才炸」两个问题。

### `clips.json` 刻意不做成 content collection

`src/content/series.json` 走的是 `file()` loader + zod schema，这次没照抄。分界线
是**这份 JSON 有没有人手写**：`series.json` 手写，zod 挡的就是手滑；`clips.json`
是生成的，该抛的错在 `clips.py` 里已经抛过且有自检覆盖，再用 zod 抄一份同样的规则
到 TypeScript 里，等于同一条约束养两个版本，改上游格式时必然只改一边。

所以放 `src/data/` 而不是 `src/content/`：后者下面的东西都是 collection，混一个
不是 collection 的进去，下一个人得读完 `content.config.ts` 才敢确定它不是。
同理不给条目编 `id` —— 没有任何东西按 id 索引单条剪藏，编出来就是个没人用、却要
保证稳定的字段。

### 上游格式变了要红一条

四个必填字段（标题 / 剪藏时间 / 原文链接 / 优先级）缺任一项抛错，界线是「缺了
这一条，这张卡片还成不成立」。优先级还多一条：必须是 `高/中/低` 之一 —— 页面
顶部的筛选按这三个值分档，一个档外的值会让这条卡片被**每一个**筛选条件都藏起来，
等于内容凭空消失。

另加一条整体检查：一份月度文件解析出 0 条也抛错。上游哪天把 `##` 换成 `###`，
逐条检查一条都不会触发（根本没有条目进入循环），站上会静默变成一个空栏目。

### 三个实测踩坑

**一、关键词不能按裸斜杠切。** 上游用 `' / '.join()` 拼关键词，而真实语料里有
`LC-MS/MS`、`敲除/敲低` 这类自带斜杠的词。按 `/` 切会把一个词劈成两个假关键词，
必须按 `' / '` 切。

**二、快照链接必须指 raw，不能指 blob。** 一开始生成的是
`github.com/Bryce505/Notes/blob/master/<路径>`。68 条逐条 curl 实测，**有一条
返回 400**：那篇标题带百分号（《…Token消耗降60%、提速50%》），文件名里那个字面的
`%` 编码出来正是 `%25`，而 GitHub 的 blob 路由对含 `%25` 的路径一律 400。
排查过程里做了关键一步 —— 拿 GitHub contents API 问它自己给这个文件什么链接，
返回的 `html_url` 与我生成的**逐字节相同，同样 400**。这证明不是编码写错了，是
那条路由的限制（`%2525`、裸 `%` 也都试过，都不行）。换成
`raw.githubusercontent.com/Bryce505/Notes/master/<路径>`，68 条逐条实测全部 200。
代价是 raw 返回纯文本不渲染 markdown，但一个打得开的链接胜过一个更好看却会 400 的。

顺带留了一条自检 `test_clips_snapshot_path_is_passed_through_verbatim`，把这个
合法的 `%25` 钉死在 fixture 里 —— 免得后人看见 `%25` 以为是二次编码，"顺手"加一个
`unquote()` 把它解掉，那样链接照样打不开。

**三、上游仓库当时是私有的。** 设计阶段我按「公开仓库，内置 GITHUB_TOKEN 就能读」
写了 workflow，实测 68 条快照链接**全部 404** 才发现 —— 本地 clone 能成功是因为
会话的 git 代理带了授权，误导了我。这个问题已由仓库改为 public 解决；`sync-clips.yml`
里留了一条注释说明它若转回私有会怎样（GitHub 对无权限的私有仓库返回 404 而不是
403，报错不指向真正的原因）。

### 导航：不是顺带修 bug，是配套改动

`Header.astro` 的 `nav` 原本是不换行的 flex。我一开始判断它「6 条导航在手机上
已经溢出」，写进了注释和设计文档 —— **实测把这个判断否掉了**。375px 下用
Chromium 量（站点 CSS 已加载）：6 条导航内容宽 **256px**、行内可用 **295px**，
正好塞得下，文档横向溢出为 0；加上「剪藏」变成 7 条才是 **343px > 295px**。

也就是说不是原本就坏，是这次新增把它顶出边界的，所以这属于本功能的配套改动，
不是 `CLAUDE.md` 说的「顺手发现的无关 bug」。已经把注释和设计文档里那个凭估算写
下的数字改成实测值。

修法是给 nav 加 `flex-wrap` 折成两行，`height: 68px` 同时换成 `min-height`
（固定高度会把折下去的第二行裁掉）。不做汉堡菜单：7 条中文导航折两行完全可读，
而折叠菜单要引入 JS 状态、焦点管理与无障碍属性，为这点收益不值得。

### 筛选是渐进增强

工具条初始带 `hidden`，由页尾脚本显出来。没有 JS 时整条不出现、68 条正常显示 ——
筛选是便利不是内容的前提，而一排点不动的按钮比没有按钮更糟。

可选字段缺失、必填字段各自缺失抛错、优先级档外抛错、0 条抛错、快照路径还原
