# 2026-08-26　系统梳理并重写 README：面向新贡献者的项目入口文档

## 背景

用户要求：基于仓库现状系统梳理并重写 README，目的是让新人（含人类贡献者
与 AI agent）读完这一份文件就能快速理解项目、快速上手开发。

实测对照旧版 README（改动前 475 行）与仓库实际状态，发现三类问题，不是
「优化一下」层面的润色：

1. **具体数字已经漂移。** 旧版「本地开发」一节写「115 项自检」，本分支
   实测跑 `pipeline/test_pipeline.py` 得到 118/118（`de8efa8` 那次提交
   新增了一条自检后就该是 118，README 没跟着改）。旧版「配置」一节写
   DeepSeek 默认模型是 `deepseek-v4-pro`，但 `pipeline/config.py` 的
   `DEEPSEEK_MODEL` 实际是 `'deepseek-v4-flash'`——`git log` 里能查到
   `3a88c83 Change DeepSeek model to 'deepseek-v4-flash'` 这次提交，
   README 同样没跟着更新。
2. **目录结构一节严重不完整。** 旧版「目录」只有 9 行，遗漏了
   `.claude/`、`.github/`、`docs/`、`logs/`、`design/`、
   `obsidian-publish-pipeline.html`、`public/`，也没提 `pipeline/` 内部
   19 个模块各自的分工——新人靠这一节完全建立不起目录心智模型。
3. **缺一个面向"新贡献者"的入口。** 旧版从「它是怎么跑的」直接跳到
   「配置（首次部署必做）」——后者是给要在自己 fork 上跑起来的人看的
   运维手册（3 个 Secret + Google Cloud 控制台一路操作），占了原文档约
   一半篇幅，却排在最前面。一个只是想读代码、跑通自检、提个 PR 的新人，
   要先滑过这一大段跟他无关的部署步骤，才能找到「怎么本地跑起来」和
   「分支/日志规矩」这些真正决定他能不能顺利提交第一个 PR 的内容。

## 实现

**只重写结构与过时事实，不改这条流水线本身的任何行为。** 本次改动只有
`README.md` 与本篇日志；`pipeline/`、`src/`、`.github/workflows/` 一行
代码都没动，因此不涉及"动了流水线行为要补自检"的要求。

**把"部署自己的 fork"和"给这个仓库做贡献"两种读者拆开。** 旧版把两者
糅在一起，新版让"这是什么→架构→目录→快速上手→内容流水线→校验器→日常
使用"服务第一种、也是默认的阅读路径，"首次部署"整节挪到后面并在开头
补一句"仓库所有者已经配好了，日常开发不需要重新走一遍"——这样两种读者
都不用跳过一大段与自己无关的内容。

**校验器相关内容从"日常使用"里独立成"校验器"一节。** 原来"校验都查
什么"挂在"日常使用"下面，跟"怎么建一个系列""图片暂缺排查"这类操作型
内容混在一起，但 `verify.py` 是 CLAUDE.md 明确点名的"仓库安全阀"、
"本项目最关键的代码"，值得单独成节、提高可发现性，而不是被淹没在一堆
使用技巧之间。

**新增内容全部可追溯到源码或已有 devlog，不引入未经验证的断言。** 「这
是什么」「架构总览」「仓库目录结构」三节里的每一条事实（三个 workflow
的触发条件、`pipeline/` 每个模块的职责、`DEEPSEEK_MODEL` 当前值、648 处
LaTeX 等）都逐一读过对应源文件或 `.github/workflows/*.yml` 后才写入，
不是凭"它应该是这样"推测。

**放弃的方案：大幅删减"首次部署"一节。** 考虑过把 Google Cloud 控制台
那一长串操作步骤精简或移到单独文件，最终放弃——那一节的每一步都标注了
"为什么需要"和"漏了会怎样"，是过去实测踩坑的直接沉淀（CLAUDE.md 要求
"注释写为什么"，这一节正是范例），删减会丢失这些一次性踩过的坑；只做了
位置调整（挪到后面）和加一句读者定位说明，内容原文保留。

**放弃的方案：给子标题加数字编号（"1. DEEPSEEK_API_KEY"）。** 旧版子
标题带编号，但编号出现在标题里会让 GitHub 自动生成的锚点变成
`#1-deepseek_api_key` 这类不直观的形式，新增的「目录」TOC 又需要手写
锚点链接——改成标题不带编号、纯文字，锚点即标题本身，TOC 链接可以直接
对应，不用去猜 GitHub 的锚点生成规则会怎么处理数字和标点。步骤的先后
顺序改用「首次部署」小节开头的一句话摘要表达（"DEEPSEEK_API_KEY →
VAULT_TOKEN → …"），不丢失顺序信息。
