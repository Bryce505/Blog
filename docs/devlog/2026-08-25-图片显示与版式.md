# 2026-08-25　图片全站不显示、版式与分组

## 背景

线上文章的图**一张都没显示过**。起因是读者反馈某篇文章有「图缺失」占位，
排查下来是五个互相独立的原因叠在一起：

1. 站点部署在 `/Blog/` 下，流水线写进正文的却是 `/images/<slug>/x.webp`。
   Astro 只对相对路径的图片做资源处理，根路径原样输出 —— 浏览器请求
   `bryce505.github.io/images/...`，**全站图片 404**
2. 图片名带空格时 `![](...)` 整条语法被当纯文本印在页面上
3. `image\202112141122601.png` 这类 Windows 反斜杠路径，POSIX 的 `Path`
   不当分隔符，basename 带着目录名，Drive 上永远查不到
4. `![[笔记#小节]]` 是笔记嵌入，跟图片嵌入同语法，被当成「找不到的图」
5. Typora 时代的 `<img src="D:\...">` HTML 标签，三条正则一条都不认 ——
   二硫键那组 16 张图有 15 张这么写

另有 5 张图是 Drive 上真的没有：早期 17 位时间戳命名，上传工具按上传时刻
重命名成 15 位，笔记引用没跟着改。

## 变更

- 新增：`remark-base-url` 构建期补 base；`remark-mark` 渲染 `==高亮==`；
  `remark-mermaid` 渲染流程图；`pipeline/repair.py` 补图通道与图片体检
- 修改：`vault.image_ref_name` 统一三处调用的引用解析；`images.url_safe`
  转义会撑破 markdown 的字符；`config.IMAGE_ALIASES` 记录改名映射；
  分组不再向上归并；版心加宽、目录左移、章节序号、mermaid 手机适配
- 删除：那篇 12 篇笔记拼成的《治疗性单抗质量属性与表征方法》及其配图

## 实现

base 补在构建期而不是让流水线写死 `/Blog/`：markdown 里不该出现部署路径，
换仓库名时只动 `site.config.mjs` 一处。

分组改成按笔记自身最深的标签层级（≤三级）分桶、碎组不向上归并。归并才是
「一篇文章什么都讲」的根源 —— 实测归并版把 12 篇横跨五个子题的笔记塞进
一组。不归并 + 最小 2 篇：30 组→38 组，覆盖面几乎不变。

改名的 5 张图用显式别名表而不是时间戳近似匹配：同一分钟撞车会把错图发
出去，对技术文章比留个占位更糟。

## 验证

自检 89 → 108 项。用 Chromium 在 1600×1100 / 768 / 390 三个视口逐页实跑：
59 张站内图全部加载、零 404、零裸 markdown、页面均不横向滚动。端到端离线
试跑（只把 DeepSeek 与 Drive 下载换成假的）连出 3 篇，零丢图零校验失败。

顺带查出校验器一个长期 bug：`DATA_NUM` 用 `\w` 当边界，而 Python 的 `\w`
把汉字算词字符，紧挨中文的数字一个都提取不到。实测那篇 HPLC 被拦下的
10 个数里 9 个原文就有 —— 白拦一次还白烧一次 token。
