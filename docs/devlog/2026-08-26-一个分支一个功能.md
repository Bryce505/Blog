# 2026-08-26　立规矩：一个分支只开发一个功能

## 背景

PR #4 把引子通道、校验器扩展、人工投稿通道、开发日志规矩四件事捆在一个
分支上，改了 18 个文件。四件都单独测过所以能合并，但真要逐行审是审不动
的；万一其中一件出问题，回滚会把另外三件一起退掉。

同时专题计划已经在另一个分支上开工，正好是「多功能并行」的场景，规矩
现在立最合适。

## 变更

- 新增：`CLAUDE.md` 的「分支与 PR」一节，规定一个分支只开发一个功能，
  并写明分支命名、日志对应关系、无关 bug 怎么处理、合并前的自测要求、
  冲突在哪里解决

## 实现

规矩写进 `CLAUDE.md` 而不是 README：README 是给使用者看的操作手册，
`CLAUDE.md` 是给开发者（含 AI）看的约定，两者读者不同。

「一个分支对应一篇开发日志」这条是配套的：一分支一功能 + 一改动一日志
文件，合并时按文件名排序即时间顺序，PR 合并不需要手工整理日志 —— 这正是
当初把日志拆成一改动一文件的原因。

实测修正允许追加到同一篇日志的「实测修正」一节，不另起新篇：分支上实跑
发现的问题跟这个分支要做的事是同一个目的，拆成两篇反而割裂。
